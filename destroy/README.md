# 💥 粉碎任意网页 · 像素大破坏

> 输入一个网址，它的标题、文字、图片、盒子全部变成**可破坏的像素关卡**——
> 拿起枪，一路向下轰，把整个页面打成一堆像素渣！

**线上开玩**：<https://bayshier.github.io/GYZApp/destroy/>

灵感致敬 [Destroy Any Website](https://destroy.spritefusion.com/)（Sprite Fusion 出品的闭源小游戏）。本项目为**净室复刻**：只复刻玩法概念，全部代码、注释、美术均为原创，未使用原项目任何代码与素材。纯原生 HTML/CSS/JS 实现，**零依赖、零构建**。

## 一、玩法

| 操作 | 桌面端 | 移动端 |
|------|--------|--------|
| 移动 | ← → 或 A D | 屏幕左下 ◀ ▶ |
| 跳跃 | ↑ / W / 空格 | 右下 ⤴ |
| 射击 | J / X / 鼠标点击 | 右下 🔫 |

- 网页的**每一段文字、每一张图片**都是平台，也是靶子——子弹打中的地方会真的破一个洞
- 网页里的**超链接**会孵出红色的「链接虫」，会咬人，也能打爆
- 一路向下推进，冲进底部的绿色「**页脚通关区**」即胜利
- 破坏率每达到 25% 会有里程碑提示；结算显示破坏率、击杀数、得分与用时

## 二、整体架构

```
用户输入网址
    │
    ▼
┌─────────────────────────────┐
│ proxy.js · 抓取层            │  浏览器直接抓别人网页会被
│ 公共 CORS 代理链依次尝试      │  CORS 拦截，所以借公共代理
│ （可替换为自建代理，见第四节）│  中转拿到 HTML 源码
└─────────────────────────────┘
    │ HTML
    ▼
┌─────────────────────────────┐
│ level.js · 关卡生成器        │  DOMParser 解析 → 按文档流
│ 标题大字/正文小字/图片成块/   │  从上往下排版到一张大画布，
│ 链接下划线 + 敌人出生点       │  再扫描像素生成实心掩码
└─────────────────────────────┘
    │ {canvas 画布, mask 掩码, enemies 敌人点, totalInk 总墨水}
    ▼
┌─────────────────────────────┐
│ game.js · 引擎               │  可破坏地形：子弹命中 → 圆形
│ 物理 / 碰撞 / 射击 / 敌人 AI  │  区域同时从画布与掩码上抹除
└─────────────────────────────┘
```

三个 JS 文件职责单一，加起来不到一千行，全部中文注释。

## 三、核心技术讲解

### 1. 可破坏地形：掩码 + 画布双层结构

这是整个项目的灵魂，思路来自《百战天虫》《Liero》的经典做法：

- **画布层**：整页内容渲染成一张 `480 × H` 的像素画（H 最高 6000）。
  每个画上去的像素（文字的笔画、图片的颜色）就是一粒「墨水」。
- **掩码层**：一个同尺寸的 `Uint8Array`，`1` 表示这个像素是实心地形，
  `0` 表示已经被打掉了。

```js
// 碰撞检测 = 查表，O(1)
solidAt(lv, x, y)  →  lv.mask[y * lv.W + x] === 1
```

**子弹命中时**，以命中点为圆心、半径 5 像素的圆内，同时把画布上的像素
透明度清零（视觉上消失）、掩码清零（碰撞上消失）——地形就真的被打出一个洞。
因为每次只读写一小块矩形区域（`getImageData/putImageData` 只取圆的外接矩形），
性能完全无压力。

构建关卡时只做**一次**全画布像素扫描来生成掩码；之后游戏中再没有全图扫描。
破坏率也是增量累计的（每次抹除返回被毁像素数），不需要反复统计。

### 2. 网页 → 像素关卡的映射规则

不是截图，而是**解析 DOM 后重新排版**，所以打碎的是"内容"本身：

| 网页元素 | 关卡形态 |
|----------|----------|
| `<h1>~<h6>` | 26px → 14px 的标题大字（打碎特别解压）|
| `<p>` `<li>` `<td>` 等正文 | 11~13px 的文字平台，逐行断行排版 |
| `<img>` | 经代理取回真实图片（失败则画"小山太阳"占位框）|
| `<pre>` `<code>` | 灰底代码块，等宽字体 |
| `<a>` 链接 | 蓝色文字 + 下划线，**并记录为敌人出生点** |
| `<hr>` | 分隔线 |
| 纯脚本渲染的 SPA 空壳 | 检测内容过少时，自动补充占位盒子保证可玩 |

### 3. 跨域抓取：为什么要代理

浏览器的同源策略不允许 `fetch` 别人的网页（没有 CORS 头）。
原版用自己的服务器做 `/api/page` 代理；本项目部署在 GitHub Pages（纯静态），
因此改为**公共 CORS 代理链**：`allorigins → corsproxy → thingproxy` 依次尝试，
单个超时 12 秒自动换下一个，全部失败可改玩**内置离线演示关卡**（零网络依赖）。

图片同理：外部图片直接画上画布会"污染"画布（之后 `getImageData` 抛安全异常，
整个破坏系统失效），所以图片也必须经代理取回 blob 再解码。

### 4. 其他细节

- **像素风渲染**：主画布整数倍放大 + `image-rendering: pixelated` + 关闭
  `imageSmoothing`，文字图片天然带像素颗粒感
- **碰撞采样**：实体矩形只采样 9 个关键点（3×3），而非逐像素检测
- **防穿墙**：子弹每帧分 3 小步推进；实体Y轴碰撞后逐像素回退
- **音效**：WebAudio 振荡器现场合成（射击/碎裂/受伤/胜负），零音频文件
- **手感**：屏幕震动、墨水飞溅粒子、无敌帧闪烁、步数领先的连击节奏

## 四、部署与自建代理（可选）

### GitHub Pages（推荐，零成本）

本目录已随仓库部署，直接访问线上地址即可。公共代理偶尔限流——
遇到抓取失败，稍等重试或玩演示关卡。

### 自建代理（更稳定，10 行 Node.js）

公共代理终究不可控。如果你有自己的服务器，跑一个极简代理：

```js
// proxy.js —— node proxy.js 跑在 3000 端口
const http = require('http');
const https = require('https');
http.createServer((req, res) => {
    const url = new URL(req.url, 'http://x').searchParams.get('url');
    if (!url) { res.writeHead(400); return res.end('需要 ?url= 参数'); }
    https.get(url, r => {
        res.writeHead(r.statusCode, {
            'Content-Type': r.headers['content-type'] || 'text/html',
            'Access-Control-Allow-Origin': '*'   // 允许游戏页跨域读取
        });
        r.pipe(res);
    }).on('error', () => { res.writeHead(502); res.end(); });
}).listen(3000);
```

然后把 `js/proxy.js` 顶部 `PROXIES` 数组的第一项改成：

```js
function (u) { return 'https://你的域名:3000/?url=' + encodeURIComponent(u); }
```
